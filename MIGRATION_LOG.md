### Adapter design decisions
- **Header-based mapping everywhere** — rows/updates/sync resolve columns by the declarative `schema.ts` headers (fixes audit H1 fuzzy-matching and the B1 class of position bugs). `normalizeRows` keys by live header and maps declared columns by trimmed header name.
- **Least privilege**: scopes = `['https://www.googleapis.com/auth/spreadsheets']` only (V3 parity). Credentials server-side only.
- **Write semantics preserved (parity)**: `_to_cells` (keep number/bool, else str), `append_rows` uses `value_input_option=USER_ENTERED` (formulas/formatting preserved), `update_cell` bool→bool/None→''/else str at header column, row = dataRowIndex+2.
- **Graceful empty**: missing/unknown tab → `[]`, never throw.
- **Cache**: TTL 300s, per-app-key; a write invalidates **only the affected table** (the required improvement).
- **Bootstrap drift**: missing declared tab → surfaced (`missingTabs`), header drift → `headerViolations`; `drift=true` rather than silent empty (A3/A4).

## Phase C — API + Authentication (server boundary)

**Date completed:** 2026-09-15 · node v22.23.2 · xlsx ^0.18.5

### Scope
Built the complete server/API boundary + authentication layer on top of the EXISTING Phase B `GoogleSheetsSource` adapter: REST endpoints for tables/import/sync/clear/metadata, server-side signed-session authentication (Option B, identity + session), role-based authorization (viewer/editor), a server-side JSONL audit log, request validation driven by `schema.ts`, and a single consistent error contract. **No Phase D/E/F work.** The 4 planning `.md` docs are UNCHANGED. Production spreadsheet never written (all write tests use FakeApi; only read-only meta/tables were exercised against the live master during a smoke run).

### Authentication (Option B — the recommended identity + session scheme)
- **Credentials** come from an env-defined `AUTH_USERS` map (`username:password:role,user2:pass2:role2`; role optional, default `viewer`) — committed nowhere, lives in gitignored `.env.local`. `.env.example` documents the schema.
- **Session cookie** `dm_session`: self-contained token = `base64url(payload) + "." + base64url(HMAC-SHA256(payload))`, wrapped in httpOnly, SameSite=Lax, `Secure` when the request is non-localhost, `Path=/`, `Max-Age=8h`. Payload = `{identity, role, iat, exp}`. Nothing sensitive is stored client-side; the payload is verified + expiry-checked on every read.
- **AUTH_SECRET** is required (>=16 chars) and must not reach the browser; missing it fails loudly at login (500 INTERNAL) and yields 401 for protected reads.
- **Constant-time password comparison** via `timingSafeEqual` over SHA-256 digests (no length/timing leak). Rejected logins still get a generic 401.
- `getSession(request)` / `requireAuth(session)` / `requireRole(session, role)` helpers used by every protected route. `requireRole` ranks roles (viewer=1 < editor=2) and distinguishes 401 (no/invalid session) from 403 (session present but role insufficient).

### Endpoints + permission matrix
| Method | Route | Role | Behavior |
|---|---|---|---|
| POST | `/api/auth/login` | **public** | validate creds → Set-Cookie; audits login success/failure |
| POST | `/api/auth/logout` | any session | expires the cookie; audits |
| GET | `/api/auth/me` | any session | returns `{identity, role}` |
| GET | `/api/tables/{key}` | viewer | `fetchTable` → normalized rows (adapter cache preserved) |
| POST | `/api/tables/{key}` | **editor** | validate object rows vs schema → `appendRows` (projection to schema column order; unknown columns rejected) |
| PATCH | `/api/tables/{key}` | **editor** | validate rowIndex/column/value → `updateCell` (column resolved by header name) |
| POST | `/api/import/{key}` | **editor** | multipart CSV/XLSX → parse server-side → project headers to schema cols → `appendRows` |
| POST | `/api/sync/wa-to-crm` | **editor** | calls the EXISTING `source.syncWaToCrm()` (B1-correct logic; not re-implemented) |
| POST | `/api/clear/{key}` | **editor** (destructive) | require `{confirm:true, tabTitle}` matching schema tab → guarded `clearTable` (adapter re-guards) — audit + identity recorded |
| GET | `/api/meta/tabs` | viewer | `listTabs()` → safe `{appKey,title,gid,drift}` (no credentials/auth internals) |

### Authorization model (minimal, internal team)
- Viewer: reads only (`GET /api/tables/{key}`, `GET /api/meta/tabs`, `GET /api/auth/me`, logout).
- Editor: all of the above plus append / update / import / sync / **clear**.
- Clear additionally requires `editor` AND explicit `{confirm:true, tabTitle}`. The adapter's own `clearSheet` guards (confirmed 2-step + appKey/tabTitle match) are retained as defense-in-depth — the API cannot be used to bypass them.

### Audit design (server-side, writes + destructive actions)
- `src/lib/audit.ts`: entries `{timestamp(ISO), actor(identity), operation, tableKey?, targetResource?, success, summary}`.
- Every append/update/import/sync/clear records an entry; login success/failure and logout are also audited.
- Persist to `data/audit.log.jsonl` (dir created lazily) via `FileAuditLog` AND mirrored to stdout. `data/` is gitignored (`/data`).
- **Never** logs private keys, auth secrets, or sensitive credential payloads.
- Writer is injectable (`AuditLog` interface + `MemoryAuditLog`/`NullAuditLog`) so tests assert entries without touching disk; `record()` never lets a sink failure throw.

### Request validation + error contract
- Every input validated before reaching the adapter: table keys / column names / row indexes / append payloads / import files / sync / clear — all resolved against `schema.ts`. Client column positions are never trusted; object rows and file headers are projected into declared schema order; unknown columns are rejected (append/update) or dropped-with-count (import).
- Single error shape `{ error: { code, message, status } }` from `src/lib/errors.ts`:
  - `AUTH_FAILED`(401), `FORBIDDEN`(403), `VALIDATION_FAILED`(400), `NOT_FOUND`(404), `ADAPTER_FAILED`(502), `INTERNAL`(500).
- Adapter/Sheet failures are generic 502 with detail logged server-side; unexpected errors are generic 500 with the detail logged and never returned. No credentials/keys/stack traces reach the client.

### Architecture for testability
Route handlers in `app/api/**/route.ts` are **thin wrappers**: they resolve the session (`getSession`), the body/params, the source (`getMasterSource`) and the audit sink, then delegate to **framework-free controller functions** in `src/server/api/*Controller.ts` that take `(session, source, ...params, auditLog) => Response`. This lets the whole Phase C suite drive the **real** `GoogleSheetsSource` over `FakeApi` with no Next server and no network. `getMasterSource()` is memoized and only constructs the network client on the first real request (never at import/build time).
